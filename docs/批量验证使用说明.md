# 批量验证使用说明

## 目标

用于正式预实验前批量运行“普通毛绒兔 CPS 测试初稿库”，检查 AI 反馈提示词是否能稳定生成 B/C/D 三类实验材料。

## 部署后访问

如果项目已经部署到 Vercel，访问：

```text
https://你的域名.vercel.app/batch.html
```

单条生成页面仍然是：

```text
https://你的域名.vercel.app/
```

## 推荐流程

1. 打开 `/batch.html`。
2. 点击“载入内置测试库”，系统会读取 `public/rabbit_cps_test_drafts.jsonl`。
3. 先只选择一个条件，例如 B，或手动删掉文本框里大部分样本，只保留 A01、A05、B10、B13、B18。
4. 点击“开始批量运行”。
5. 确认模型调用、数据库保存、中文显示都正常后，再选择 B/C/D 三个条件运行全集。
6. 运行结束后点击“下载结果JSONL”，保存本次批量验证结果。

## 运行规模

内置测试库共 25 份初稿。

如果 B/C/D 三个条件都勾选：

```text
25 份初稿 × 3 个反馈条件 = 75 条反馈记录
```

页面会逐条调用现有 `/api/feedback`，而不是一次性提交 75 条，因此更适合 Vercel 部署，不容易因为单次请求过长而超时。

## 检查重点

- B 组是否只显示结果性分数。
- C 组是否显示结构化评价，但不显示专家 CMC 元认知示范。
- D 组是否额外显示专家 CMC 元认知示范。
- 同一份初稿在 B/C/D 条件下核心评分是否一致。
- 高风险样本是否被谨慎评分。
- 功能堆叠样本是否没有被高估。
- 只写 AI、APP、传感器等技术标签但没有机制说明的样本是否没有被自动加高分。
- 是否存在乱码、JSON 解析失败、评分越界、直接替学生改写方案等问题。

## Vercel 环境变量

确认 Vercel 项目里已经配置这些环境变量：

```text
AI_API_URL
AI_API_KEY
AI_MODEL
AI_TEMPERATURE=0
AI_MAX_TOKENS=2200
AI_RESPONSE_FORMAT=json_object
SUPABASE_URL
SUPABASE_SERVICE_ROLE_KEY
SUPABASE_TABLE=feedback_records
```

如果接口不支持严格 JSON 输出，可将：

```text
AI_RESPONSE_FORMAT=none
```

## 注意

批量验证会真实调用模型并写入数据库。建议被试编号前缀使用 `pilot`、`promptcheck` 或 `batchtest`，以便后续和正式实验数据区分。
